## 1. Summary of what the machine actually exposes

Everything below was verified by reading the interface, not assumed from the spec sheet.

### CPU — Intel Core i7-14650HX

* 24 logical CPUs (16 cores / 2 threads on P-cores), 1 socket, 1 NUMA node.
* `intel_pstate` driver, `powersave` governor, 800 MHz – 5200 MHz.
* Per-CPU frequency: `/sys/devices/system/cpu/cpu*/cpufreq/scaling_cur_freq`.
* **Throttle counters exist** and are the authoritative throttling signal:
  `/sys/devices/system/cpu/cpu0/thermal_throttle/{core,package}_throttle_count`
  (observed at boot: `core_throttle_count=3`, `package_throttle_count=31`).
  These are monotonic counters — a *delta* means throttling happened now.
* Temperatures via `coretemp` (hwmon6): `Package id 0` plus per-core labels
  (`Core 8`, `Core 12`, `Core 16`, `Core 20`, …). `temp*_crit = 100000` (100 °C).
* Load / scheduling: `/proc/loadavg`, `/proc/stat`.
* **PSI is enabled**: `/proc/pressure/{cpu,io,memory}` — cheap, high-signal
  stall metrics that beat naive utilisation for "is the machine actually struggling".

### Memory

* 31 926 304 kB total (~30.4 GiB usable), 8 GiB swap, zswap present but unused.
* `/proc/meminfo`, `/proc/vmstat` (for `oom_kill`, `pgmajfault`), `/proc/pressure/memory`.

### GPUs — hybrid, and this is the single most important finding

| | Intel | NVIDIA |
|---|---|---|
| DRM node | `card1` / `renderD128` | `card2` / `renderD129` |
| PCI | `0x8086:0xa78b` | `0x10de:0x2d59` (RTX 5060 Laptop) |
| Driver | `i915` | `nvidia` 595.91.07 (open kernel module) |
| Runtime PM | `active` (drives eDP-1) | `suspended` (D3cold) |

* Intel exposes real metrics unprivileged: `gt_act_freq_mhz`, `gt_cur_freq_mhz`,
  `gt/gt0/rc6_residency_ms`, and **eleven `throttle_reason_*` flags**
  (`thermal`, `pl1`, `pl2`, `pl4`, `prochot`, `vr_tdc`, …).
* NVIDIA: `libnvidia-ml.so.1` is present at
  `/usr/lib/x86_64-linux-gnu/libnvidia-ml.so.1` → NVML via `dlopen`, no build dep.
* `/proc/driver/nvidia/gpus/0000:01:00.0/power` reports
  `Runtime D3 status: Enabled (fine-grained)`, `Video Memory: Off`.

> **⚠ Measured hazard:** the dGPU was in `suspended`. Running `nvidia-smi` **woke it**,
> and it stayed `active` for ~9 seconds before returning to `suspended`
> (observed: `active → active → suspending → suspended` over 12 s).
>
> Any monitor that polls NVML on a timer would hold an RTX 5060 permanently awake and
> cost several watts continuously. **The daemon must read
> `/sys/class/drm/card2/device/power/runtime_status` first and only touch NVML when the
> GPU is already awake.** This constraint is baked into the collector design.

* Per-process GPU usage is available **unprivileged** via DRM fdinfo —
  verified on a live `gnome-shell` fd: `drm-driver: i915`, `drm-engine-render: … ns`,
  `drm-total-system0`, etc. That gives real per-client GPU engine time without root.

### Battery / power

* `BAT0` is an **energy-domain** battery (µWh/µW, not charge/µAh):
  `energy_now`, `energy_full=91 183 000`, `energy_full_design=90 004 000`,
  `power_now` (µW), `voltage_now`, `status`, `cycle_count`, `capacity`.
  Observed live: `Discharging`, 93 %, `power_now=21 744 000` → **21.7 W**.
* Health = `energy_full / energy_full_design` = **101.3 %** (new pack; the formula must
  tolerate >100 % rather than reporting a bug).
* `ADP0/online` = AC present. A USB-C PD source PSY also exists
  (`ucsi-source-psy-USBC000:001`) with `curr1_input` / `in0_input` in hwmon5.
* **RAPL is root-only** here: `/sys/class/powercap/intel-rapl:0/energy_uj` is
  `-r-------- root root`. CPU-package wattage therefore needs the privileged helper;
  on battery, `BAT0/power_now` already gives true whole-system draw.

### Thermals & fans

Nine hwmon devices. The useful ones:

| hwmon | name | provides |
|---|---|---|
| hwmon0 | `ADP0` | — |
| hwmon1 | `acpi_fan` | `fan1_input` |
| hwmon2 | `acpitz` | `temp1_input` |
| hwmon3 | `BAT0` | `in0_input`, `power1_input` |
| hwmon4 | `nvme` | `Composite`, `Sensor 1`, `Sensor 2` + `temp1_crit`, `temp1_alarm` |
| hwmon5 | `ucsi_source_psy` | `curr1_input`, `in0_input` |
| hwmon6 | `coretemp` | `Package id 0` + per-core |
| hwmon7 | **`asus`** | **`fan1_input`=`cpu_fan` (2300 rpm), `fan2_input`=`gpu_fan` (2400 rpm)** |
| hwmon8 | `asus_custom_fan_curve` | 8-point fan curves (read-only for us) |

Thermal zones: `acpitz`, `INT3400`, `SEN3`, `TCPU`, `TCPU_PCI`, `x86_pkg_temp`.
Cooling devices include per-CPU `Processor` and `PCIe_Port_Link_Speed_*`.

### Storage

* `nvme0n1` 953.9 G — **WD PC SN5000S SDEQNSJ-1T00-1002**, fw `34230100`, `state=live`.
* Root is `nvme0n1p7` (293 G, ext4). Also BitLocker/NTFS Windows partitions (dual boot).
* **37 snap `loop*` mounts.** Every one is a read-only squashfs at 100 % use.
  A naïve "filesystem > 90 %" rule fires 37 false criticals on this machine — the
  storage collector must filter pseudo/read-only/loop mounts. Verified, not theoretical.
* `/proc/diskstats` gives per-device IO incl. `io_ticks` (field 10) for utilisation
  and weighted-time for latency.
* `/sys/fs/ext4/nvme0n1p7/errors_count` = 0 — a free, unprivileged filesystem-error signal.
* **NVMe SMART needs root**: `/dev/nvme0` is `crw------- root root`, and neither
  `nvme-cli` nor `smartmontools` is installed. → privileged helper, or degrade.

### Network

| iface | driver | state |
|---|---|---|
| `wlp108s0` | `rtw89_8852ce` (Realtek RTL8852CE) | up, carrier 1 |
| `enp109s0` | `r8169` (Realtek Ethernet) | down, carrier 0 |
| `lo` | — | up |

* `/proc/net/wireless` gives link quality 69, level **−41 dBm** — unprivileged, no
  `iw`/`nl80211` round-trip needed for the common case.
* `/sys/class/net/*/statistics/*` — 24 counters per iface incl. `rx_errors`,
  `rx_dropped`, `tx_errors`, `rx_crc_errors`, `rx_missed_errors`.
* Link/addr/route changes are available event-driven via `RTMGRP_LINK` /
  `RTMGRP_IPV4_IFADDR` / `RTMGRP_IPV4_ROUTE` rtnetlink groups — no polling required.

### Bluetooth / audio / USB / camera

* Bluetooth `hci0` (IMC Networks radio, USB `13d3:3612`), `rfkill` shows
  soft-block no / hard-block no. A **connection appears as a child node**
  `/sys/class/bluetooth/hci0:1` — that is the unprivileged "connected devices" signal.
* PipeWire, pipewire-pulse and WirePlumber are all `active` (user units).
  Sound cards `card0` (HDMI/dGPU audio) and `card1` (analog).
* USB: `Shinetech ASUS FHD webcam` (`3277:0096`) and the BT radio.
* V4L2: `video0`/`video1` = **ASUS FHD webcam**, `video2`/`video3` = **ASUS IR camera**.

### System / journal / suspend

* The user is in the **`adm` group** → full journal readable *without root*,
  including `journalctl -k` kernel messages. Verified.
* One genuinely failed unit at discovery time:
  **`snap.openshell.gateway.service`** — a perfect real-world test case for the
  "ignore this service" feature.
* `CLOCK_BOOTTIME − CLOCK_MONOTONIC` = 0.0 s (no suspend yet this boot). This
  difference is exactly the cumulative time spent suspended, so **suspend/resume can be
  detected and measured with two `clock_gettime` calls and no DBus subscription.**
* Session bus at `/run/user/1000/bus`; `notify-send` present; `org.freedesktop.UPower`,
  `org.freedesktop.login1`, `org.bluez`, `org.freedesktop.systemd1`,
  `org.freedesktop.NetworkManager` all on the system bus.

## 2. Interface selection matrix

The interface actually used for each subsystem, chosen from the above.

| Subsystem | Interface | Privilege | Mode |
|---|---|---|---|
| CPU util / load | `/proc/stat`, `/proc/loadavg` | none | poll fast |
| CPU pressure | `/proc/pressure/cpu` | none | poll fast |
| CPU freq | `cpufreq/scaling_cur_freq` | none | poll medium |
| CPU temp | hwmon `coretemp` | none | poll medium |
| CPU throttling | `cpu*/thermal_throttle/*count` | none | poll medium (delta) |
| Memory | `/proc/meminfo`, `/proc/vmstat` | none | poll fast |
| OOM kills | `/proc/vmstat:oom_kill` + journal | none | delta + event |
| Intel GPU | `card1/gt_act_freq_mhz`, `rc6_residency_ms`, `throttle_reason_*` | none | poll medium |
| NVIDIA GPU | `runtime_status` gate → NVML `dlopen` | none | conditional |
| Per-proc GPU | DRM fdinfo `drm-engine-*` | none (own procs) | poll slow |
| Battery | `/sys/class/power_supply/BAT0/*` | none | poll medium |
| AC | `ADP0/online` | none | poll medium + uevent |
| CPU package W | `intel-rapl:0/energy_uj` | **root** | helper |
| Temps / fans | hwmon `coretemp`,`asus`,`nvme`,`acpitz` | none | poll medium |
| Filesystems | `statvfs()` + `/proc/self/mountinfo` | none | poll slow |
| Disk IO | `/proc/diskstats` | none | poll fast |
| FS errors | `/sys/fs/ext4/*/errors_count` | none | poll slow |
| NVMe temp | hwmon `nvme` | none | poll medium |
| NVMe SMART | ioctl `NVME_IOCTL_ADMIN_CMD` log 0x02 | **root** | helper |
| Net throughput | `/sys/class/net/*/statistics/*` | none | poll fast |
| Net link events | rtnetlink `RTMGRP_LINK`/`_IFADDR`/`_ROUTE` | none | **event** |
| Wi-Fi signal | `/proc/net/wireless` | none | poll medium |
| Reachability | `connect()` to gateway / DNS / TCP 443 | none | poll slow |
| Bluetooth | `/sys/class/bluetooth/*`, `/dev/rfkill` | none | poll slow + event |
| Audio | systemd user unit state, `/sys/class/sound` | none | poll slow |
| USB / camera | `/sys/bus/usb`, `/sys/class/video4linux` | none | poll slow + **uevent** |
| Hotplug | netlink `NETLINK_KOBJECT_UEVENT` | none | **event** |
| systemd units | DBus `org.freedesktop.systemd1` | none | poll slow + signal |
| Journal | `journalctl -f -o json -p 4` child, streamed | `adm` | **event** |
| Suspend/resume | `CLOCK_BOOTTIME − CLOCK_MONOTONIC` | none | derived |
| Notifications | DBus `org.freedesktop.Notifications` | session | event |
| Inventory | DMI, `/proc/modules`, PCI/USB IDs | none | on change |

Everything marked "none" is what the daemon uses by default. Only two metrics in the
entire application need elevated rights, and both degrade cleanly to "unsupported".
